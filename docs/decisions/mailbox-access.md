# 세린 전용 접근

## Decisions

- 계정은 세린 하나뿐이다. Supabase Auth의 새 가입은 끄고, 앱에는 가입 화면과 가입 링크를 두지 않는다.
- 세린 계정은 배포 전에 Supabase 대시보드에서 한 번 직접 만든다.
- 앱은 설정값으로 지정한 세린의 이메일로 로그인한 경우에만 세린의 우체통과 답장·버리기 기능을 연다. 그 밖의 계정은 로그인하더라도 이 기능과 데이터에 접근할 수 없다.
- 이 확인은 화면이 아니라 데이터를 내주는 쪽(서버와 DB)에서 한다. 화면을 숨기는 것만으로 막지 않는다.

## Boundaries

- 친구는 로그인하지 않는다. 엽서 보내기, 모두의 엽서 읽기, 비밀 우체통 열기는 이 계약의 대상이 아니다.
- 세린이 여러 명이 되거나 다른 사람에게 연하장을 열어 주는 기능은 이 계약이 허락하지 않는다. 그런 기능은 이 계약을 다시 정한 뒤에 만든다.

## Why

가입이 열려 있으면 누구든 먼저 가입해 로그인하는 순간 세린의 우체통에 들어올 수 있다. 가입을 닫고 계정을 직접 만들면 이 문제는 막히지만, 대시보드에서 실수로 가입을 다시 켜거나 다른 계정이 생기는 경우가 남는다. 세린의 이메일을 한 번 더 확인하면 설정 실수가 있어도 다른 계정은 아무것도 볼 수 없다. 세 장치 모두 구현 비용이 작다.

## Reconsider when

- 연하장 주인이 두 명 이상이 되거나, 누구나 자기 연하장을 열 수 있는 서비스로 바뀔 때
- 세린이 다른 이메일로 계정을 옮겨야 할 때 (설정값만 바꾸면 되는지 먼저 확인)

## Still-rejected alternatives

- 가입 닫기와 직접 생성만 하고 이메일 확인은 생략 — 대시보드 설정 실수 한 번에 다른 계정이 우체통에 들어올 수 있다.
- 처음 가입한 사람을 주인으로 삼기 — 배포 직후 누가 먼저 가입하느냐에 운이 걸린다.
